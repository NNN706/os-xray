# os-xray

**Клиент Xray для OPNsense: полный JSON-редактор, подписки и необязательный обход через WAN при отказе прокси.**

[English](README.md) · [Скачать v4.0.0-rc.1](https://github.com/NNN706/os-xray/releases/tag/v4.0.0-rc.1) · [Статус проверок](docs/TESTING.md)

> **Предварительный выпуск для изолированного тестового роутера.** Переносимые тесты выполняются на Linux. Реальные TUN/PF, переключение, перезагрузка и откат на OPNsense/FreeBSD ещё требуют испытаний. Это не стабильный выпуск для рабочего роутера.

## Возможности

- Полный JSON-редактор с подсветкой, нумерацией строк, сворачиванием, поиском, форматированием и изменением высоты.
- Импорт JSON, VLESS-ссылки или HTTPS-подписки. Несколько outbounds, Routing, балансировщики и observatory сохраняются в одной конфигурации.
- **Один активный туннель.** Можно хранить несколько профилей, но одновременно работает только один.
- Проверка активного соединения с HTTP-кодом и задержкой.
- Необязательный heartbeat и перевод явно выбранного клиентского трафика на WAN при отказе прокси.

Плагин не заменяет Unbound, не меняет системный DNS, не устанавливает BIRD/DNSTAP и не переписывает чужие gateways или общий default-маршрут.

## Перед установкой

Нужна изолированная OPNsense с резервной копией конфигурации и консольным доступом. Выпуск — установочный архив, **а не нативный пакет `.pkg`**.

Следующие компоненты должны быть установлены заранее:

| Компонент | Ожидаемый путь |
| --- | --- |
| PHP / штатный framework OPNsense | `/usr/local/bin/php` |
| Xray-core | `/usr/local/bin/xray-core` |
| tun2socks | `/usr/local/tun2socks/tun2socks` |
| curl | `/usr/local/bin/curl` |

Установщик сообщает об отсутствующих зависимостях; Xray-core и tun2socks он не скачивает и не заменяет. Ядро должно поддерживать импортированный JSON — это проверяет **Validate**. Node.js на роутере не требуется. Debian используется для сборки и тестов, не для установки плагина.

## Установка предварительного выпуска

Скачивайте **версионный asset из Releases**, а не автоматически созданный GitHub архив «Source code» и не отдельный `install.sh` из raw-ветки. Release содержит весь плагин и уже собранный редактор.

В shell OPNsense от root:

```sh
workdir=$(mktemp -d /root/os-xray-install.XXXXXX)
cd "$workdir"
fetch -o os-xray-v4.0.0-rc.1.tar.gz https://github.com/NNN706/os-xray/releases/download/v4.0.0-rc.1/os-xray-v4.0.0-rc.1.tar.gz
fetch -o manifest.json https://github.com/NNN706/os-xray/releases/download/v4.0.0-rc.1/manifest.json
fetch -o SHA256SUMS https://github.com/NNN706/os-xray/releases/download/v4.0.0-rc.1/SHA256SUMS
sha256 -q os-xray-v4.0.0-rc.1.tar.gz
sha256 -q manifest.json
cat SHA256SUMS
```

**Сравните оба показанных хеша с соответствующими строками SHA256SUMS. При любом несовпадении остановитесь.** Контрольная сумма обнаруживает повреждение, но не является независимой подписью издателя.

После совпадения обеих сумм:

```sh
tar -xzf os-xray-v4.0.0-rc.1.tar.gz
cd os-xray-v4.0.0-rc.1
sh install.sh
```

Сохраните распакованный каталог для последующего удаления. Установщик перезапускает configd, чтобы OPNsense зарегистрировала действия плагина. Скачанная подписка автоматически не применяется, новый туннель автоматически не запускается.

## Первое подключение

1. Обновите веб-интерфейс и откройте **VPN → Xray**.
2. Включите плагин на вкладке **General**. Создайте или откройте профиль на **Instances**.
3. Нажмите **Import JSON / URL / VLESS** или вставьте полный JSON. Поле `remarks` либо `Remarks`, если присутствует, используется как имя профиля.
4. В JSON должен быть loopback SOCKS-inbound без авторизации, например `127.0.0.1:10808`. Плагин использует его и не создаёт недостающий inbound молча. При неоднозначности выберите нужный.
5. Нажмите **Validate Config**, сохраните профиль, затем **Apply** или переподключитесь вручную.
6. Нажмите **Test**, чтобы проверить действующее соединение через SOCKS.

Назначение интерфейса, адреса, gateways и начальные правила клиентского трафика нужно настроить в OPNsense. Сам запуск процесса ещё не направляет LAN-трафик в туннель. Перед включением управляемой маршрутизации прочитайте [инструкцию](docs/HEARTBEAT.ru.md).

### Validate, Test и Apply

| Кнопка | Действие |
| --- | --- |
| **Validate Config** | Проверяет открытый JSON, включая несохранённые правки, установленным Xray-core. |
| **Test** | Проверяет применённое соединение через SOCKS и его Routing/балансировщик. Показывает HTTP-код и время до первого байта. Предел запроса — 1000 мс. |
| **Apply / переподключение** | Проверяет и активирует сохранённую/подготовленную конфигурацию. При отказе запуска пытается восстановить предыдущую рабочую версию. |

«Use DNS from configuration» по умолчанию включено. При выключении блок `dns` остаётся в редакторе, но исключается из рабочей копии. Системный DNS роутера не меняется.

## Подписки и обновления

Импортируйте HTTPS URL через окно импорта. Запрос выполняет роутер с `User-Agent: OPNSense`, проверкой TLS и пределом 2000 мс. Если пришло несколько конфигураций, выберите одну по remarks; автоматически они не объединяются.

**Auto Update Subscription** по умолчанию выключено. При включении выберите интервал из заголовка подписки либо ручной — 1–24 часа. Отсутствующий/неверный интервал подписки останавливает обновление по расписанию; причина показана в интерфейсе.

**Обновление подписки никогда не перезапускает туннель.** Меняется подготовленный JSON; активирует его **Apply** или ручное переподключение. Успешное обновление заменяет ручные правки подготовленного JSON; об этом предупреждает диалог. Ошибка загрузки или проверки сохраняет предыдущую версию.

## Heartbeat и обход через WAN

Необязательный heartbeat обращается к Cloudflare `generate_204` через существующий SOCKS и ожидает HTTP 204 за 2 секунды. Интервалы: 15 секунд, 30 секунд, 1, 2 или 5 минут. Адрес проверки должен идти через proxy по вашему JSON; успешного пути, выбранного балансировщиком, достаточно.

Один сбой запрашивает bypass через WAN; три последовательных успеха возвращают proxy. Панель показывает состояние компонентов, последний результат, задержку, историю и устаревшие/ошибочные состояния. Время обнаружения также зависит от интервала и блокировок перехода состояния.

Bypass ограничен явно подключёнными правилами firewall с `[os-xray]` в начале описания и выбранными существующими TUN/WAN gateways. Можно направить весь трафик, выбранный этими правилами, либо только назначения ASN/CIDR. Внутри туннеля дополнительно работает Xray JSON Routing. Чужие gateways, их мониторинг/force_down и общий default-маршрут сохраняются.

**В bypass также не действуют BLOCK-правила Xray JSON.** Постоянные запреты задавайте правилами OPNsense выше подключённых правил плагина. При переключении существующие соединения могут переподключаться. Перед включением bypass прочитайте [подробную инструкцию](docs/HEARTBEAT.ru.md).

## Обновление и удаление

Перед обновлением сохраните конфигурацию роутера и архив предыдущего выпуска. Проверьте и распакуйте новый версионный release, запустите его установщик. Проверьте перенесённые профили, выполните Validate и Apply. Старые исходные поля при конвертации сохраняются. Само обновление плагина не применяет подготовленные изменения подписки.

Для удаления из распакованного каталога выпуска:

```sh
sh install.sh uninstall
```

Туннель останавливается; подключённый трафик переводится в WAN, если это настроено. Сохранённые профили и бинарные файлы ядра остаются. После удаления проверьте ранее подключённые правила firewall. Если остановка не удалась, удаление прерывается с сохранением файлов плагина.

## Если что-то не работает

- **Не найдена зависимость:** установите компонент по указанному пути и повторите установку.
- **Validate не проходит:** проверьте место ошибки JSON и поддержку параметров установленным ядром.
- **Нет трафика через туннель:** проверьте назначение TUN, gateway и правила LAN; затем Test и heartbeat.
- **Fallback показывает unknown/stale:** проверьте подключённые правила/gateways и состояние служб. Такой статус не подтверждает успешное переключение.
